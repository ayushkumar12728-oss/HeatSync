# Model Artifacts

This directory holds the trained Urban Heat Island (UHI) model artifacts. The
artifacts are generated by the AI pipeline and are **not committed to the
repository** (they are large binaries and are rebuilt by the pipeline).

## Required file

| File | Purpose |
|---|---|
| `models/best_model.pkl` | **Required for local inference.** joblib-serialised fitted regressor (XGBoost by default). Loaded once by the backend `ServingContext` and reused for every prediction/simulation request. |

## Optional file

| File | Purpose |
|---|---|
| `models/best_model.onnx` | ONNX export of the same model (opset 15), verified against onnxruntime at export time. Currently informational; the backend serves inference from the `.pkl`. |

## How it is generated

```bash
cd ai-engine
python main.py
```

The pipeline (11 steps) produces `best_model.pkl` (+ `.onnx`) as STEP 7 output,
together with `data/outputs/metrics.json` (evaluation metrics),
`data/outputs/reports/leakage_report.json` (the exact feature list — the single
source of truth for the prediction feature set) and
`data/feature_engineering/training_dataset.csv` (used to rebuild the
preprocessor). Requirements are in `requirements.txt` / `requirements-dev.txt`.

## Compatible feature set

- The model is trained on the features listed in
  `data/outputs/reports/leakage_report.json` → `kept`.
- **Leakage columns are never features:** `Target_LST`, `MeanLST`, `MaxLST`,
  `MinLST` and any column with `|corr| > 0.99` to the target are removed at
  training time.
- **`Grid_ID` is never a feature** (it is a spatial-order proxy).
- The backend enforces the exact training-time feature order; unknown input
  columns are dropped, missing features are median/mode-imputed exactly as at
  training time.
- If `leakage_report.json` is missing but `best_model.pkl` exists, the backend
  falls back to the feature names stored inside the fitted model.

## Model version

The version reported by `GET /api/model/info` is the installed `xgboost`
package version captured at serving time (best effort). Retraining with a new
XGBoost release may change results; pin versions for reproducibility.

## Is it required?

- **Local inference / prediction API / scenario simulation: YES.** Without
  `best_model.pkl` the API returns a clear `model_unavailable` status
  (HTTP 503) and the frontend disables predictions — nothing is fabricated.
- The 3D map, OSM layers, monitoring, legends, analytics and risk indicators
  all continue to work without the model.
